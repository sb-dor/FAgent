# Доработки после проверки: конфигурации запуска и поле ввода

Первая волна правок после того, как пользователь проверил приложение после M6. Три части: кнопка
«Запустить» с конфигурациями из `.vscode/launch.json`; очередь сообщений по ⌘↵; перетаскивание файлов
и картинки в поле ввода. Уже сделано в этой же ветке (`ux-round-1`, `db14148`): кнопка Stop чата
показывает `CircularProgressIndicator`, пока ход останавливается.

Готово, когда: «Запустить» запускает выбранную конфигурацию, а его ▾ выбирает из Default и
конфигураций `launch.json` проекта; пока агент работает, ⌘↵ ставит сообщение в очередь, и очередь
уходит по ходам; файлы и картинки, брошенные на чат, попадают в поле ввода, картинки — агенту как
изображения.

Решения пользователя: конфигурации — `launch.json` + Default (без редактора в приложении); устройство
конфигурации побеждает чип; очередь — ⌘↵, список над полем; файлы вне проекта — абсолютным путём;
картинки — настоящими изображениями; бросать можно на весь чат; одна спека на всё.

## Установленные факты (2026-11-04)

- Сейчас у проекта один набор аргументов запуска (`RunArguments`: flavor, `--dart-define`, свои флаги;
  drift `run_configs`, строка на проект); устройство, режим и цель — в `RunViewState`
  (`selectedDeviceId`, `mode`, `target`); `IAppRunRepository.start(projectId, device:, mode:, target:,
  arguments:)`; окружение процесса — `ShellEnvironment` приложения. Свои флаги не могут содержать
  зарезервированные (`-d/--device-id`, `-t/--target`, режимы, `--flavor`, `--dart-define`);
  `--dart-define-from-file` разрешён.
- `launch.json` VS Code — JSON с комментариями и висячими запятыми (как в присланном пользователем
  файле). Поля dart-конфигурации: `name`, `type`, `request`, `program`, `cwd`, `args`, `toolArgs`,
  `deviceId`, `flutterMode`, `env`, `preLaunchTask`.
- Очереди сообщений в приложении нет: пока агент работает, Send выключен, Enter и ⌘↵ ничего не делают
  (`PromptComposer._onKey`).
- Вложения сейчас — только «＋»: `@путь` для файла проекта, файл вне проекта отклоняется
  (`attachOutsideProject`); при отправке упоминания становятся ресурсами. Картинки не отправляются.
- Все три агента принимают картинки: `promptCapabilities.image: true` у Claude (адаптер 0.96.0),
  Codex (2.5.0) и Gemini (0.66.0). Хаб пробрасывает дополнительные блоки prompt как есть
  (`AgentHub.prompt(..., resources:)`).
- Пакеты (pub.dev, проверено): `desktop_drop` 0.9.2 (2026-10-20, 150 баллов) — перетаскивание файлов на
  macOS/Windows/Linux; `pasteboard` 0.6.0 (2026-10-22) — картинка из буфера обмена.

## 1. Конфигурации запуска

- «Запустить» — сплит-кнопка: основная часть запускает выбранную конфигурацию (подпись
  `▶ Запустить · <имя>`, обрезается, полное имя во всплывающей подсказке); ▾ открывает меню: «Default»
  (сегодняшние аргументы, правка — «Аргументы запуска…», как сейчас), конфигурации из
  `.vscode/launch.json` в порядке файла (выбранная отмечена), «Открыть launch.json» (или «Создать
  launch.json», если файла нет — создаёт `{"version": "0.2.0", "configurations": []}` и открывает в
  редакторе). Пока приложение запущено, основная часть — «Стоп», как сейчас; меню доступно, выбор
  действует со следующего запуска.
- Выбор запоминается по проекту по имени (drift `run_configs` получает столбец `selectedConfig`,
  `null` = Default; схема v10). Пропавшее из файла имя → Default.
- Чтение: при открытии меню и перед каждым запуском. Разбор терпит комментарии `//` и `/* */` и висячие
  запятые. Берутся только `"type": "dart"` с `"request": "launch"`; остальные не показываются.
  - `program` → цель; `args` и `toolArgs` раскладываются: `--flavor`/`--flavor=` → flavor,
    `--dart-define`/`--dart-define=` → define, `-d`/`--device-id` → устройство, `--release`/`--profile`/
    `--debug` → режим, остальное (в т.ч. `--dart-define-from-file=…`) — свои флаги как есть;
    `deviceId` и `flutterMode` — устройство и режим; `env` — к окружению процесса `flutter run`.
  - `${workspaceFolder}` → папка проекта. `cwd`, отличный от папки проекта, или другая переменная
    `${…}` → конфигурация серая с причиной («Не поддерживается: ${env:HOME}»). `preLaunchTask` →
    подзаголовок «задача перед запуском пропускается».
  - Нечитаемый файл → одна строка в меню «launch.json не читается: <причина>»; Default работает.
- Устройство и режим: выбор конфигурации с устройством/режимом переключает чипы; чипы остаются
  переключаемыми (выбор пользователя после этого — на этот запуск). Устройства конфигурации нет среди
  подключённых → «Запустить» выключена: «Устройство web-server недоступно».
- Вне рамок: редактор конфигураций в приложении, `attach`, составные конфигурации, выполнение
  `preLaunchTask`.

## 2. Очередь сообщений

- Пока агент работает (статус занят), ⌘↵ в непустом поле ставит сообщение в очередь чата и очищает
  поле; Enter в это время по-прежнему ничего не делает. Когда агент свободен, ⌘↵ = отправить.
- Подсказка: рядом с Send маленькое `⌘↵ В очередь` — только пока агент работает и поле не пустое; в
  пустом поле во время работы — плейсхолдер «Агент работает — ⌘↵ поставит сообщение в очередь».
- Очередь над полем: строки по порядку (первая строка текста + число вложений), у каждой ✎ (вернуть в
  поле, убрав из очереди) и ✕. Сообщение хранит свои вложения и картинки на момент постановки.
- Нормальный конец хода → уходит первое из очереди, следующее — после его хода. Ход закончился
  ошибкой, входом или остановкой пользователем → очередь на паузе: «Очередь на паузе» и «Отправить
  следующее»; сама после сбоя не продолжает.
- Очередь — в памяти, по чату. Выход с непустой очередью спрашивает, как выход с занятым чатом.

## 3. Перетаскивание и картинки

- Бросать можно на весь чат: при наведении чат затемняется с «Отпустите, чтобы прикрепить»; бросок
  уходит в поле этого чата, в позицию курсора (`desktop_drop`).
- Файл проекта → `@относительный/путь`; папка проекта → `@относительная/папка/`; файл или папка вне
  проекта → абсолютный путь простым текстом (в обратных кавычках, если есть пробелы); картинка (`png`,
  `jpg`, `jpeg`, `gif`, `webp`) → чип картинки. Несколько файлов — в порядке броска.
- Картинки: брошенные и вставленные ⌘V (`pasteboard`) — чипы-миниатюры над текстом поля с ✕;
  отправляются ACP-блоками `{type: "image", mimeType, data}` после текста; в отправленном сообщении
  чата — миниатюры. Не больше 10 картинок по 5 МБ; больше — отказ одной строкой. Агент без
  `promptCapabilities.image` (свой агент) → «Этот агент не принимает картинки», картинка не
  добавляется.

## Ошибки и края

| Случай | Поведение |
| --- | --- |
| `launch.json` нет | Меню: Default и «Создать launch.json» |
| `launch.json` не JSON | Строка «launch.json не читается: …»; Default работает |
| Неподдержанный `cwd` / переменная | Конфигурация серая с причиной |
| Выбранная конфигурация пропала | Default |
| Устройства конфигурации нет | «Запустить» выключена с причиной |
| Ход закончился ошибкой/входом/остановкой | Очередь на паузе, «Отправить следующее» |
| Выход с очередью | Вопрос, как для занятого чата |
| Картинка > 5 МБ / больше 10 | Отказ одной строкой |
| Агент без картинок | «Этот агент не принимает картинки» |
| Брошена папка вне проекта | Абсолютный путь текстом |

## Тестирование

- Чтение `launch.json`: присланный пользователем файл как фикстура (висячие запятые), комментарии,
  другие `type`/`request`, неподдержанные `cwd` и переменные, битый файл; раскладка аргументов;
  `env`. Репозиторий: запоминание выбора, откат на Default; миграция v9 → v10. Шапка: подпись и запуск
  сплит-кнопки, меню, чипы за конфигурацией, недоступное устройство, «Открыть/Создать launch.json»;
  аргументы и окружение, с которыми уходит `flutter run`.
- Очередь: ⌘↵ ставит только пока занят; подсказка и плейсхолдер; отправка по одному; пауза на
  ошибке/входе/остановке; ✎ и ✕; вопрос при выходе.
- Перетаскивание и картинки: каждый случай броска (файл и папка проекта, путь вне проекта, картинка,
  несколько); лимиты; агент без картинок; вставка; блоки картинок в prompt; миниатюры в ленте.
  Настоящий бросок из Finder — руками.

## Решения

- Конфигурации — из `launch.json` проекта плюс Default; файл — источник, приложение его не правит
  (кроме создания пустого).
- Устройство и режим конфигурации переключают чипы, чипы остаются за пользователем.
- Очередь только по ⌘↵ во время работы агента, в памяти, с паузой после сбоя.
- Файлы вне проекта — абсолютным путём; картинки — ACP-изображениями с лимитами.
