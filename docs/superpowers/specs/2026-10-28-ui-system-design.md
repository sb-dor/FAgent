# UI system design: flutter_code_agent

_Согласовано с Avaz в брейншторме 2026-10-28. Макеты: [`docs/design/`](../../design/) — по ним
раскладка и состав экранов; цвета и размеры — по этому документу (он главнее при расхождении)._

## Цель

Довести интерфейс приложения до вида «Claude Code Desktop, но для Flutter» сразу целиком: все разделы,
которые появятся в вехах M2–M6, получают готовый UI уже сейчас. Там, где логики ещё нет, экраны
работают на фейковых репозиториях с правдоподобными данными; по мере вех меняется только реализация
репозитория, а UI и контроллеры остаются.

Что сказал пользователь:
- нужен дизайн и логика как у Claude Code Desktop, но для Flutter;
- разделы: запуск и устройства, скиллы и best practices, агенты/модели/MCP, новый проект;
- скиллы — встроенная библиотека плюс свои (папка, git, редактор), включаются глобально или на
  проект;
- результат шага — спека + макеты, затем реализация во Flutter.

Принятые в брейншторме решения:

| Вопрос | Решение |
|---|---|
| Стиль | Нейтральный, холодные серые, акцент Flutter `#0175C2`; своё лицо, не клон Claude |
| Навигация | Как Claude Code Desktop: сайдбар чатов по проектам; Скиллы и Настройки — экраны окна; запуск — вкладка Run правой панели + кнопки в шапке |
| Подход | Всё в приложении; для будущих фич — интерфейсы репозиториев + `Fake*` реализации с бейджем «Preview» |
| Скиллы | Формат Anthropic Skills (`SKILL.md`); источники: встроенные, мои, проект, git |
| Запуск | Привязан к проекту, не к чату; агент управляет им через MCP |

Критерий готовности: по приложению можно пройти все экраны макетов кликами (en и ru, светлая и
тёмная тема), настоящие данные там, где они уже есть (чаты, лента, diff, план, вход Claude, модель и
режим), фейковые с бейджем «Preview» — в остальных местах; `flutter analyze` чистый, виджет-тесты
экранов проходят.

## 2. Окно и навигация

### Раскладка

```
┌ AppTitleBar: ◧ | заголовок чата · проект |  [📱 устройство ▾] [▶ Run] [⚡] | ◨ ┐
├ Sidebar 236 ┬ Chat (лента ≤ 720 по центру + поле ввода) ┬ RightPane 340–560 ┤
```

- Сайдбар скрывается (⌘\), правая панель скрывается (⌘J) и тянется мышью (340–560 px, ширина
  запоминается).
- Окно: по умолчанию 1280×800, минимум 900×600 (как сейчас). Уже 1100 px правая панель по
  умолчанию закрыта.

### Экраны окна (без роутера)

Навигация — состояние в `WorkspaceDataController`: `WorkspaceView { chat, skills, settings }` и
выбранный раздел страницы. Глубоких ссылок и истории нет, поэтому octopus не нужен (правило CLAUDE.md
«plain widgets inside workspace» сохраняется). Скиллы и Настройки целиком заменяют сайдбар, чат и
панель; «← Чат» и Esc возвращают к тому же чату, агенты работают в фоне.

Диалоги поверх окна: новый проект (560 px), доверие к папке, подтверждение bypass, выход.

### Горячие клавиши

⌘N новый чат · ⌘K поиск по чатам · ⌘\ сайдбар · ⌘J правая панель · ⌘, настройки · ⌘R hot reload ·
⇧⌘R hot restart · ⇧Tab режим разрешений · Esc закрыть меню/страницу · ↵ / Esc на карточке
разрешения. Список — в Настройки → Горячие клавиши (только просмотр в этой версии).

## 3. Экраны

Макеты: `1-window.html` … `6-new-project.html` в `docs/design/`.

### 3.1 Сайдбар
- «Новый чат» (⌘N) в текущем проекте, «Поиск» (⌘K) — по названиям чатов всех проектов.
- Группы по проектам, сворачиваются; меню ⋯ проекта: Показать в Finder, Настройки проекта (скиллы и
  MCP проекта), Убрать из списка.
- Строка чата: `StatusDot` — синяя (агент работает), жёлтая (ждёт разрешения), красная (ошибка),
  нет точки (простаивает).
- «＋ Проект ▾»: Открыть папку… · Новый Flutter-проект… · Клонировать из git….
- Низ: «Скиллы», «Настройки», строка агента по умолчанию со статусом входа.

### 3.2 Шапка окна
Название чата и проекта; справа устройство запуска, ▶ Run / ■ Stop, ⚡ hot reload — те же действия,
что во вкладке Run (общий контроллер запуска проекта).

### 3.3 Лента чата
Без изменения модели `ChatTranscript`, меняется оформление:
- сообщение пользователя — справа, плашки `@файл` / `⚠ ошибка` / `🎯 виджет` внутри текста;
- размышления — свёрнутая строка «▸ Размышления · 12 с»;
- инструменты — компактная строка (иконка, заголовок, путь), чтение группируется («Прочитал 4
  файла»), правка — счётчик `+84 −0`, клик открывает diff в правой панели (этап 4: вкладка
  «Изменения»; на этапе 3 не реализовано);
- использованный скилл — строка «🧩 Скилл feature-architecture» (этап 5: нужно хранилище скиллов);
- изменённые файлы хода, конец хода, системные события — как сейчас, в новых токенах.

### 3.4 Поле ввода
Текст: `@` — контекст, `/` — скиллы и команды. Под текстом чипы `SelectorChip`:
- **＋** — прикрепить файл или картинку (картинки — после поддержки агентом; пока только файл);
- **Агент** — меняется только до первого сообщения чата (этап 3 показывает агента чата; выбор
  другого — M5, пока есть только Claude);
- **Модель** и **Усилие** — из `configOptions` агента (меню A); галочка «по умолчанию для новых
  чатов» пишет в настройки;
- **Режим разрешений** — меню B, тон чипа: warn для Accept edits/Auto, danger для Bypass;
- **🧩 N** — скиллы этого чата (меню F) — этап 5, вместе со хранилищем скиллов.

Меню «/» (C): скиллы проекта, команды приложения (`/run`, `/reload`, `/restart`, `/screenshot`),
команды агента (`availableCommands` из ACP). Меню «@» (D): файлы проекта (уже есть), выбранный
виджет, последняя ошибка запуска, скриншот устройства — секция «Из запуска» (виджет, ошибка,
скриншот) появится на этапе 4 вместе с Run.

Решения этапа 3, уточняющие спеку:
- Enter на карточке разрешения отвечает только `allow_once` (никогда постоянным разрешением) и
  только при пустом поле ввода; «Всегда в этом проекте» — только кнопкой.
- «Отклонить и сказать…» использует только `reject_once`.
- Умолчания для новых чатов (модель, усилие, режим) не хранят режим bypass: он никогда не
  включается без диалога подтверждения, ни из умолчаний, ни по ⇧Tab.

### 3.5 Карточка разрешения
Тон warn; заголовок по типу (команда, правка, чтение вне проекта), тело — команда моноширинно или
diff; кнопки по `options` агента: основная — первая allow (↵), «Всегда в этом проекте» (allow_always),
«Отклонить» (Esc), «Отклонить и сказать…» (отклоняет и ставит фокус в поле ввода).

### 3.6 Правая панель
Вкладки `PaneTabs`:
- **Изменения N** — файлы, изменённые в этом чате (из `turn_files` и diff инструментов), по клику —
  `DiffView`;
- **Run** (бейдж с числом ошибок) — макет 3: устройство, режим (debug/profile/release), точка
  входа; стоп, hot reload, hot restart, выбор виджета, скриншот, DevTools; строка состояния;
  переключатель «Hot reload после каждого хода агента»; логи с фильтром «Все / Ошибки / Агенту» и
  поиском; блок ошибки с «→ Отправить агенту» и «Открыть файл»; прогресс сборки; результат выбора
  виджета с «＋ В сообщение»;
- **План** — последний `PlanItem` чата со статусами пунктов.

Запуск принадлежит проекту: все чаты проекта видят один запуск.

«Агенту» в логах и в блоке ошибки не отправляет сообщение: ошибки попадают в черновик поля ввода
(чат не запускается сам) и помечаются отправленными. DevTools, скриншот и аргументы запуска ждут M2
— в заглушках запуска они помечены Preview.

### 3.7 Скиллы и правила (экран)
Навигация 220 px: «Скиллы», «Правила», источники (Встроенные, Мои, Проект, git-источники, «＋
источник»). Список 320 px с поиском, тегом источника и переключателем. Карточка (min 400 px):
описание, «когда применять», область включения (все проекты + исключения), файлы, редактор
`SKILL.md` с frontmatter; действия «Дублировать в Мои» (для встроенных), «Попробовать в чате».
«＋ Добавить»: Создать · Из папки… · Из git-репозитория… · Сгенерировать с агентом (новый чат с
заготовленным промптом). Селектор проекта в шапке переключает, для какого проекта показаны
переключатели.

- **Скилл** — папка с `SKILL.md` (frontmatter `name`, `description`) и файлами; агент подгружает сам
  или по `/имя`.
- **Правило** — короткий Markdown, действует всегда, уходит агенту в начале сессии.

Решения этапа 5:
- Одна модель `KnowledgeItem` (скилл или правило) и один поток `watch` вместо `Skill`/`Rule` и
  `watchSkills`/`watchRules`; порядок в списке — источник, затем имя.
- Чтение, запись и дублирование получают корень проекта явно (`projectRoot`), а не берут его из
  состояния репозитория: два окна наблюдения за разными проектами (окно и экран) живут одновременно.
- Проектные скиллы и правила включаются только по проекту, общего переключателя у них нет (id не
  содержит проекта, глобальная строка протекла бы в другие проекты с тем же именем).
- Git-источники: только «＋ Добавить источник…» с меткой Preview, без выдуманных скиллов.
- Меню F («Скиллы» в поле ввода) без выбора на чат до M3: он появится вместе с доставкой агенту.
- Папки скиллов опрашиваются раз в 2 с (watcher файловой системы пока не нужен).
- «Попробовать в чате» и `/имя` работают только для проектных скиллов до M3: до доставки через MCP
  (M3) приложение не передаёт агенту остальные скиллы.

### 3.8 Настройки (экран)
Навигация 220 px (уже 1100 px окна — иконки 56 px); контент — одна колонка по центру, **max 640
px**, отступы 32; карточки только в одну колонку, внутри перенос, а не обрезка. Разделы:
- **Общие** — язык (системный / en / ru), агент по умолчанию, поведение при закрытии;
- **Агенты** — карточка на агента: версия, статус, вход/выход/установка (вывод в карточке), модель,
  усилие и режим по умолчанию, ссылка на настройки Claude; «＋ Свой ACP-агент»;
- **MCP-серверы** — встроенные (сервер приложения, Dart MCP; выключаются только по проекту) и свои
  (stdio, HTTP, импорт `.mcp.json`) со статусом и числом инструментов;
- **Разрешения** — сохранённые «Всегда в этом проекте» по проектам, с удалением;
- **Flutter** — SDK (в том числе fvm проекта), сводка `flutter doctor` с «Исправить с агентом», org и
  шаблон нового проекта, где открывать DevTools;
- **Внешний вид** — тема (системная/светлая/тёмная), плотность ленты;
- **Горячие клавиши** — список.

Решения этапа 6:
- Каталог настроек агента (модель, усилие, режим) хранится в `app_settings` под ключом `agentOptions`
  (агент → `configOptions`); его пополняет `AgentHub(onConfigOptions:)` при каждой сессии, из него
  строятся меню модели/усилия/режима по умолчанию. Пустой каталог — подсказка «откройте чат с
  агентом», выдуманных списков нет.
- Статус Claude — `--cli auth status --json` через закреплённый адаптер, выход — `--cli auth logout`.
  Проверка идёт в своей группе процессов и убивается целиком по таймауту (иначе `npx` умирает, а его
  дочерние `node` остаются).
- Codex, Gemini и свой ACP-агент — Preview до M5: кнопки сообщают «Появится в M5», агентом по умолчанию
  они стать не могут.
- У `mcp_servers` нет столбца `projectId`: переключатель по проекту — таблица `mcp_server_states`
  (`serverKey`, `projectId`, `enabled`; строка есть, только когда сервер выключен в проекте).
  Встроенные серверы выключаются только по проекту, свои — глобально и по проекту. Серверы не уходят
  агенту до M3 (доставка через `session/new` → `mcpServers`).
- Разрешения читают и правят только `permissions.allow` в `.claude/settings.local.json` каждого
  проекта: туда адаптер Claude пишет «Всегда в этом проекте». Общий `.claude/settings.json` не
  читается и не меняется.
- Новые поля `AppSettings`: `askBeforeQuit`, `feedDensity`, `projectOrg` (проверяется `orgPattern`),
  `projectTemplate`, `devToolsTarget`; нечитаемое значение становится значением по умолчанию.
- Flutter: путь к SDK и версия fvm проекта настоящие; версия Flutter и сводка `flutter doctor` —
  Preview до M4, шаблон «git» — M4, DevTools внутри приложения — M2.

### 3.9 Новый проект (диалог 560 px)
Поля: имя пакета (проверка как у `flutter create`), org (из настроек), папка, платформы (чипы),
шаблон (Моя архитектура · Чистый flutter create · Из git-шаблона), «git init + первый коммит»,
«Открыть чат после создания». Затем прогресс: `flutter create` → `git init` → шаг агента (обычный чат
«Новый проект» со своими разрешениями) → `flutter analyze` → коммит. Диалог можно свернуть.

Решения этапа 7:
- Правила имени взяты из `flutter_tools` (`create_base.dart`): строчные латинские буквы, цифры и `_`,
  не с цифры; не слово Dart; не `collection`, `flutter`, `flutter_test`, `meta`. `suggestPackageName`
  намеренно отличается от `flutter create`: `-` и пробелы становятся `_`, прочие недопустимые символы
  отбрасываются, а если не осталось ни буквы, ни цифры — подсказки нет.
- Цель — новая папка `<родитель>/<имя>`; всё, что уже лежит по этому пути (папка, даже пустая, файл,
  ссылка), запрещено (`TargetProblem.exists`); нет самого родителя — `parentMissing`. «Создать»
  доступно, только когда имя, org (`orgPattern`), цель (проверка завершена) и хотя бы одна платформа
  в порядке и найден Flutter SDK.
- Родитель по умолчанию: родитель последнего открытого проекта, если он есть на диске; иначе
  `~/StudioProjects`, если есть; иначе домашняя папка. Org и шаблон берутся из настроек; сохранённый
  шаблон «git» в форме заменяется на «Мою архитектуру».
- Создание — поток снимков `Stream<List<CreationStep>>` (весь список шагов при каждом изменении, поток
  закрывается после последнего шага). Шаги зависят от запроса: `git init` и коммит — при «git init +
  первый коммит», шаг агента — только у шаблона «Моя архитектура». Поток, закончившийся шагом
  `failed`, — это `failed`, а не `completed`.
- `ProjectCreationController` живёт на уровне окна (`WorkspaceConfigWidget`), создание одно за раз;
  закрытие диалога (Свернуть, Esc) его не останавливает, диалог не закрывается кликом по фону. Пока
  создание идёт или ждёт «Готово», диалог открывается сразу на прогрессе; «Готово» закрывает диалог и
  после его исчезновения сбрасывает контроллер.
- Чип прогресса («Создаю имя · N/M» / «имя: готово» / «имя: ошибка», у завершённого есть ✕) стоит
  в сайдбаре сразу под кнопкой «＋ Проект», к которой относится; нажатие открывает диалог на прогрессе.
- Репозиторий — `FakeProjectCreationRepositoryImpl` (правило фейков, §4); `checkTarget` и
  `defaultParent` настоящие (читают диск и таблицу проектов), `create` ничего не пишет и не создаёт
  чат: проигрывает шаги с задержкой и выводом. `isPreview` → «имя: готово (Preview)» и пометка в
  диалоге. «Открыть чат агента» и настоящий шаг агента — M4.
- «Из git-шаблона…» в форме и «Клонировать из git…» в меню «＋ Проект» остаются SnackBar «Появится в
  M4», без выдуманной формы.

### 3.10 Пустые и ошибочные состояния
Нет проектов (приглашение открыть или создать) · проект без чатов · агент не установлен / нужен вход
(карточка с действием, как сейчас) · нет устройств (подсказка запустить эмулятор) · Flutter SDK не
найден (ссылка в Настройки → Flutter) · MCP-сервер недоступен (статус и «Войти»/«Повторить»).

### Фейковые репозитории
- Файл `data/fake_<name>_repository.dart`, класс `Fake<Name>RepositoryImpl implements I<Name>Repository`.
- Выбор реализации — в `initialize_dependencies.dart`; в `Dependencies` хранится интерфейс.
- Данные детерминированные, с задержками как у настоящих операций, без случайности (тесты
  стабильны).
- У модели или репозитория флаг `isPreview`; UI показывает `PreviewBadge`, действия, которые
  ничего не делают, честно говорят «Появится в M2» (снекбар), а не притворяются.
- Замена на настоящую реализацию — одна строка в инициализации и удаление фейка.

### База данных (v3 → v4)
v4 добавляет только таблицу `app_settings` (`key` PK, `value` JSON, `updatedAt`). Таблицы `skill_states`
(`skillId`, `projectId` nullable, `enabled`; уникальный ключ `(skillId, projectId)`), `mcp_servers`
(`id`, `name`, `transport`, `config` JSON, `enabled`, `createdAt`) и `mcp_server_states` (`serverKey`,
`projectId`, `enabled`; почему без `projectId` в `mcp_servers` — в решениях этапа 6, §3.8) добавили этапы 5 и 6
своими миграциями (схема теперь v6). Миграция step-by-step + тест `SchemaVerifier`, как v3.

## 5. Локализация и доступность

## 6. Тестирование
- Виджет-тесты каждого экрана на фейках: сайдбар, поле ввода и меню, карточка разрешения, вкладки
  правой панели, Скиллы, каждый раздел Настроек, мастер нового проекта; en и ru; светлая и тёмная
  тема (рендер без исключений и переполнений на 900×600 и 1280×800).
- Юнит-тесты репозиториев с Real-реализацией (`app_settings`, `skills` на временной папке,
  `chat_search`), миграции v3 → v4.
- Golden-тесты не делаем: шрифты на CI отличаются.

## 7. Порядок реализации
Каждый этап — отдельный план и коммит(ы), после каждого `flutter analyze` и тесты:

1. Дизайн-система: токены, тема, JetBrains Mono, общие виджеты.
2. Каркас окна: шапка, сайдбар (группы, поиск ⌘K, меню проекта), правая панель с вкладками,
   переключение экранов, горячие клавиши, `app_settings` (v4).
3. Чат: оформление ленты, поле ввода с чипами и меню A/B/C/D/F, карточка разрешения.
4. Правая панель: Изменения и План (Real), Run и выбор виджета (Fake).
5. Скиллы и правила: экран, файловое хранилище, включение по проектам.
6. Настройки: все разделы; агенты (Claude Real, остальные Fake), MCP, Flutter.
7. Новый проект: диалог и прогресс (Fake).
