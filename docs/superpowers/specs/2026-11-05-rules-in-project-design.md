# Правила в проекте: скиллы внутри правил, `docs/rules`, `AGENTS.md`

Ветка `rules-in-project` (от `main`). Встроенные скиллы сливаются со своими правилами; правила
перестают уходить в системный промпт и живут в проекте файлами `docs/rules/*.md`, а `AGENTS.md`
и `CLAUDE.md` проекта велят агенту читать их первыми. Содержимое правил дальше дополнит
пользователь; эта веха — устройство и перенос того, что есть.

## Установленные факты (2026-11-05)

- Встроенное знание — `assets/knowledge/`: 8 правил `rules/*.md` (~130 строк всего) и 8 скиллов
  `skills/<имя>/SKILL.md` (~860 строк) с примерами `templates/*.dart`; читает
  `AssetBuiltinKnowledge` (`feature/skills/data/builtin_knowledge.dart`), папки перечислены в
  `pubspec.yaml`.
- Правила уходят агенту текстом: `promptRules` (включённые, кроме `AGENTS.md`, и для Claude — кроме
  `.claude/rules`) → `buildRulesPrompt` → `SessionContext` по `rulesChannel` агента
  (`feature/session_context/data/session_context_repository.dart`). Там же уходит `AGENTS.md`
  проекта (Codex читает его сам), а если `CLAUDE.md` подключает его строкой `@AGENTS.md`, текст не
  дублируется.
- Новый проект (`ProjectCreationRepositoryImpl`): шаги `flutterCreate`, `gitInit`, `skeleton`
  (шаблон `assets/project_template/architecture/`, только у шаблона «архитектура»), `analyze`,
  `firstCommit`. Ни `docs/`, ни `CLAUDE.md`, ни `AGENTS.md` сейчас не пишутся.
- Таблица `projects` (схема 11) уже хранит разрешение на запуск настроек проекта
  (`project_trust`): его диалог показывается при выборе проекта — образец для нового диалога.

## 1. Знание

- Каждый скилл вливается в своё правило; новых правил нет:

  | Скилл | Правило |
  | --- | --- |
  | `feature-architecture` (+ примеры) | `architecture` |
  | `controller-patterns`, `paginated-controller` (+ примеры) | `controllers` |
  | `dependency-injection` (+ пример) | `dependencies` |
  | `repository-streams` (+ пример), `drift-migration` | `repositories` |
  | `pub-freshness` | `package-freshness` |
  | `widget-test` | `widgets` |

  `generated-files` и `localization` — как есть.
- Примеры `.dart` переходят в правила блоками ```` ```dart ````: файлом `.dart` в `docs/rules`
  их проверял бы анализатор проекта. Повторы между скиллом и правилом не дублируются: правило —
  одно связное руководство с разделами.
- Встроенных скиллов не остаётся (`assets/knowledge/skills/` и их строки в `pubspec.yaml`
  удаляются). Раздел «Скиллы» остаётся для своих и проектных скиллов; MCP-инструменты скиллов
  работают как прежде.
- У каждого правила новое однострочное `description` — его видят диалог и `AGENTS.md`.

## 2. Как правила доходят до агента

- Встроенные правила больше не уходят в системный промпт (`promptRules` пропускает
  `SkillSource.builtin`). Свои и проектные правила — как сейчас.
- Проект получает правила файлами:
  - `docs/rules/<имя>.md` — текст правила без frontmatter;
  - в `AGENTS.md` — раздел между метками `<!-- flutter_code_agent:rules -->` и
    `<!-- /flutter_code_agent:rules -->`:
    «Before changing code, read the rules in `docs/rules/` that apply to the task. They are this
    project's conventions:» и список «- `docs/rules/<имя>.md` — <description>»;
  - в `CLAUDE.md` — строка `@AGENTS.md` (Claude Code подключит `AGENTS.md`, приложение не
    продублирует его текст).
- Запись идемпотентна: файла нет — создаётся; файл есть — раздел между метками заменяется, а без
  меток дописывается в конец; `@AGENTS.md` дописывается, только если такой строки нет. Чужой текст
  этих файлов не трогается; существующий `docs/rules/<имя>.md` перезаписывается.

## 3. Новый проект

- Новый шаг `rules` перед `firstCommit` (у обоих шаблонов): пишет включённые встроенные правила,
  `AGENTS.md` и `CLAUDE.md` по п. 2; файлы входят в первый коммит. Подпись шага —
  «Правила проекта» / “Project rules”.
- Такой проект сразу помечен «правила предложены»: диалог п. 4 для него не появляется.

## 4. Проект без `docs/rules`

- Когда: при открытии или добавлении папки проекта и при первом выборе проекта из сайдбара, если в
  проекте нет `docs/rules` и для него ещё не предлагали (новый столбец `projects.rules_offered`,
  схема 12, по умолчанию `false`). После диалога разрешения на запуск, если тот тоже показывается.
- Диалог «Добавить правила в проект?» / “Add the project rules?”:
  - пояснение: «Агент будет читать их из `docs/rules` — так они видны в проекте и меняются вместе с
    ним.» / “Agents will read them from `docs/rules`, so they live and change with the project.”;
  - список встроенных правил с флажками: имя и `description`; по умолчанию отмечены включённые;
  - **Добавить** (активна, если отмечено хоть одно) пишет отмеченные по п. 2; **Не сейчас** —
    ничего не пишет. В обоих случаях `rules_offered = true`.
- Раздел «Правила» на экране скиллов, когда выбран проект без `docs/rules`: кнопка «Добавить правила
  в проект» / “Add rules to project” — тот же диалог.
- Ничего не коммитится: изменения остаются в рабочем дереве.
- Ошибка записи (нет прав, диск) — сообщение с текстом ошибки; `rules_offered` не меняется.

## 5. Переключатель встроенного правила

- Встроенное правило не уходит в промпт, поэтому его переключатель теперь значит «отмечено по
  умолчанию в диалоге и пишется в новый проект». Подсказка под переключателем меняется:
  «Добавляется в новые проекты» / “Added to new projects”.

## Ошибки и края

| Случай | Поведение |
| --- | --- |
| `docs/rules` уже есть | Диалог не показывается; кнопки нет |
| `AGENTS.md` или `CLAUDE.md` уже есть | Раздел заменяется или дописывается, `@AGENTS.md` — только если нет |
| Ни одно правило не отмечено | «Добавить» неактивна |
| Все встроенные правила выключены | Новый проект без `docs/rules`; диалог предлагает их неотмеченными |
| Запись не удалась | Сообщение; `rules_offered` остаётся `false` |
| Проект удалён из сайдбара и добавлен снова | Новая строка `projects`: диалог снова |

## Тестирование

- Ассеты: у каждого правила есть разделы влитых скиллов, ни одного `SKILL.md` не осталось,
  `pubspec.yaml` их не перечисляет; библиотека без встроенных скиллов.
- Промпт: встроенные правила в нём не появляются, свои — да.
- Запись правил (на временной папке): создание файлов; `AGENTS.md` с чужим текстом — раздел
  дописан, повторная запись заменяет его, а не дублирует; `CLAUDE.md` без и с `@AGENTS.md`.
- Новый проект: шаг `rules` пишет файлы до первого коммита; проект помечен.
- Диалог (виджет, macOS): появляется один раз; снятие флажка; «Добавить» пишет только отмеченные;
  «Не сейчас» запоминается; кнопка в «Правилах»; 900×600 en/ru, светлая/тёмная.
- Миграция 11 → 12: столбец есть, у существующих проектов `false`.

## Решения

- Правила — файлами в проекте, системный промпт их не несёт; `AGENTS.md` указывает на них,
  `CLAUDE.md` подключает `AGENTS.md`.
- Старые проекты — диалог один раз, с выбором правил; потом кнопка.
- Встроенных скиллов нет; раздел «Скиллы» остаётся.

## Не в этой вехе

Новое содержимое правил от пользователя (следующий шаг), обновление `docs/rules` в проекте при
выходе новой версии правил, правила для не-Flutter проектов.
