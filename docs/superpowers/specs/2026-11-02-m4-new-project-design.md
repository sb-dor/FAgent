# M4: Мастер нового проекта

Веха M4 из `docs/PLAN.md`: настоящее создание проекта из мастера (UI этап 7,
`2026-10-28-ui-system-design.md` §3.9). Готово, когда: «Создать» с шаблоном «Моя архитектура»
даёт проект, который открывается в приложении, проходит `flutter analyze` и `flutter test` без
замечаний, лежит в git с первым коммитом, и агент в его первом чате продолжает эту архитектуру.

## Цель и рамки

Мастер (форма, прогресс, чип, контроллер, список шагов) уже есть; ненастоящий только
`create` (`FakeProjectCreationRepositoryImpl` ничего не пишет). M4 ставит за тот же интерфейс
`IProjectCreationRepository` настоящий репозиторий, который запускает `flutter`, `git` и пишет
скелет архитектуры сам, без агента.

Вместе с M4: настоящая версия Flutter в `IFlutterSdkRepository.sdkFor` (её показывает форма; в коде
она помечена «до M4»).

Вне рамок: шаблон «Из git-шаблона…» и «Клонировать из git…» (остаются с пометкой «Появится позже»),
`flutter doctor` (у команды нет машинного вывода; остаётся Preview), выбор агента (M5).

## Установленные факты (проверены перед спекой, Flutter 3.47.1)

- `flutter create` принимает `--org`, `--project-name`, `--platforms <список через запятую>` и
  `--[no-]pub`.
- `flutter pub add` добавляет несколько пакетов за раз, `dev:` — в `dev_dependencies`, git-зависимость —
  `"control@{git:{url: …, ref: …}}"`. Без версии ставится последняя подходящая.
- `flutter analyze` по умолчанию `--fatal-infos` и `--fatal-warnings`: любое замечание даёт
  ненулевой код выхода.
- `flutter --version --machine` печатает JSON с `frameworkVersion` и `channel`.
- `flutter doctor` машинного вывода не имеет.
- gen-l10n строится на `flutter pub get`, когда в `pubspec.yaml` под `flutter:` стоит
  `generate: true` и в корне есть `l10n.yaml` (так устроен этот репозиторий).
- Релиз `control` на pub.dev без `handle(..., error:)`, которым пользуются шаблоны скиллов: пакет
  закрепляется на тот же git-коммит, что в `pubspec.yaml` этого репозитория.

## 1. Скелет (`assets/project_template/architecture/`)

Шаблон — настоящие файлы проекта. После `flutter create` они заменяют сгенерированные `lib/` и
`test/`; `l10n.yaml` ложится в корень. Это наименьшее приложение по правилам архитектуры:

```
lib/main.dart                                  appZone → $initializeApp → runApp(dependencies.inject(child: App()))
lib/src/common/
  utils/app_zone.dart                          runZonedGuarded + FlutterError.onError, лог через `l`
  utils/error_util.dart                        ErrorUtil.logError
  widget/app_error.dart                        экран, если инициализация упала
  localization/localization.dart               Localization.of(context) поверх gen-l10n
  localization/intl_en.arb                     заголовок приложения и текст главного экрана
lib/src/feature/initialization/
  models/dependencies.dart                     Dependencies (один сервис: SharedPreferencesWithCache) + inject()
  widget/dependencies_scope.dart               DependenciesScope, updateShouldNotify → false
  widget/app.dart                              MaterialApp с делегатами локализации, home: HomeScreen
  data/initialization.dart                     $initializeApp(onSuccess:, onError:)
  data/initialize_dependencies.dart            именованные шаги, у каждого в логе длительность
lib/src/feature/home/widgets/home_screen.dart  локализованная заглушка — первое, что заменят
test/widget_test.dart                          pump App с тестовыми Dependencies, находит заголовок
l10n.yaml                                      arb-dir lib/src/common/localization, вывод в generated/
```

- Подстановка одна: `{{package}}` — имя пакета в импортах `package:`. Org применяет `flutter create`.
- Пакеты: `flutter pub add` без версий — `l`, `shared_preferences`, `freezed_annotation`, `intl`,
  `flutter_localizations` (`sdk: flutter`), `dev:freezed`, `dev:build_runner`; `control` — git-пин
  (константа в коде рядом с репозиторием, равная пину этого `pubspec.yaml`; тест сверяет их).
- `build_runner` не запускается: в скелете нет `@freezed`. Он стоит для первой фичи агента.
- Нет базы, API-клиента, роутера, примера фичи (агент добавляет их по скиллам), своего
  `analysis_options.yaml` (остаётся от `flutter create`), `CLAUDE.md` и `AGENTS.md` (правила
  приложение и так отдаёт агенту в каждом чате). Язык один — английский.
- Ассеты шаблона перечислены в `pubspec.yaml` и исключены из анализа этого репозитория
  (`analysis_options.yaml` `exclude`), как `test/fixtures/knowledge_templates/`. Файлы шаблона — Dart
  с `{{package}}` в импортах, поэтому проверяются только через сгенерированный проект (тестирование).

## 2. Шаги

Список шагов прежний (`creationStepsFor`): `git init` и коммит — при «git init + первый коммит»,
шаг скелета — только у «Моей архитектуры». `CreationStepKind.agentSetup` переименовывается в
`skeleton`, подпись «The agent lays out the architecture» → «Architecture skeleton» (ru: «Скелет
архитектуры»).

Команды идут с Flutter SDK, который показывает форма (`IFlutterSdkRepository.sdkFor(null).path`),
и с окружением `ShellEnvironment` (`which('git')` для git). Каждая — через `GroupedProcess`, своей
группой процессов. Строки stdout и stderr вместе уходят в `CreationStep.output` (показываются
последние 6), у шага замеряется `took`.

1. **`flutter create`** — `flutter create --org <org> --project-name <name> --platforms <список>
   <path>`; у «Моей архитектуры» ещё `--no-pub`.
2. **`git init`** — `git init` (ветка по умолчанию — из `init.defaultBranch` пользователя).
3. **Скелет** — копирует шаблон с подстановкой (строка `✎ <путь>` на файл), вставляет
   `generate: true` под `flutter:` в `pubspec.yaml`, `flutter pub add` пакетов раздела 1, `flutter
   pub get`.
4. **`flutter analyze`** — шаг падает при ненулевом коде выхода.
5. **Первый коммит** — `git add -A`, `git commit -m "Initial commit"`.

Упавший шаг (ненулевой код, исключение) получает `failed`, следующие остаются `pending`, поток
закрывается. Созданное остаётся на диске. Вывод упавшего шага — и есть причина: например, git без
имени и почты печатает своё «Please tell me who you are»; имя и почта не подставляются. Нет `git` —
шаг `git init` падает со строкой «git not found». Нет `flutter:` в `pubspec.yaml` — шаг скелета
падает со строкой, что вставить `generate: true` некуда.

## 3. Конец создания

- **Успех.** Проект добавляется в список так же, как «Открыть папку» (`IProjectOpeningRepository.open`),
  и помечается доверенным (`IProjectTrustRepository.trust`): все его файлы написало приложение. Он не
  выбирается: пользователь мог свернуть диалог и уйти в другой чат.
- **«Готово» становится «Открыть проект»** рядом с «Закрыть». Чип в сайдбаре по-прежнему открывает
  диалог.
- **«Открыть проект»** выбирает проект и, если включено «Открыть чат после создания», начинает чат
  агентом по умолчанию через `createChat` (как «＋ Чат»): пустой composer, ничего не отправляется.
  Диалог закрывается, контроллер сбрасывается.
- **«Закрыть»** закрывает диалог и сбрасывает контроллер; проект остаётся в сайдбаре.
- **Неудача после `flutter create`** (упали analyze, коммит, скелет): проект есть и рабочий — он
  добавляется так же, диалог предлагает «Открыть проект» и «Закрыть». **`flutter create` упал** —
  ничего не добавляется, только «Закрыть».
- Кто добавляет проект: репозиторий, как часть потока (после последнего шага, если `flutter create`
  прошёл). Поток становится `Stream<CreationRun>`, где `CreationRun` (freezed) — `steps` и
  `int? projectId` (появляется в последнем снимке); `completed` и `failed` контроллера получают
  `projectId`. Ошибка добавления — ошибка создания.
- Убираются: кнопка «Открыть чат агента» на прогрессе, всё Preview создания (`isPreview`, заголовок
  «(Preview)», пометка `newProjectPreviewNote`, SnackBar «Появится в M4»), заметка о чате «Новый
  проект» (`newProjectProgressNote`) и подпись агента (`newProjectAgentName`). Подсказка шаблона
  «Моя архитектура» говорит, что приложение раскладывает `lib/src/common` + `feature` само.
- «Из git-шаблона…», «Клонировать из git…» и сегмент «git» в Настройках → Flutter показывают
  «Появится позже» (новый ключ `comingLater`) вместо «Появится в M4».

## 4. Остановка, выход, зависания

- **«Остановить»** рядом со «Свернуть», пока создание идёт. Вызывает
  `IProjectCreationRepository.stop()`: репозиторий убивает группу процессов текущей команды
  (`GroupedProcess.stop`), шаг получает `failed` и строку «Stopped», следующие не запускаются, поток
  доходит до конца как при любой неудаче — проект добавляется по правилам раздела 3. Отмена подписки
  (закрытие окна, `dispose`) — жёсткий путь: процесс убит, проект не добавляется.
- **Таймаутов нет**: медленная сеть не должна валить создание, которое бы закончилось. Выход —
  «Остановить».
- **Выход из приложения** во время создания: `AppCloseRepository.shutdown` вызывает новый
  `IProjectCreationRepository.dispose()`, который убивает текущий процесс. Написанное остаётся на
  диске, проект не добавляется. Вопрос при выходе создание не считает (он про чаты).
- `create` следует правилам «Stream-Returning Methods»: отмена подписки останавливает шаг и убивает
  процесс, поток закрывается после последнего шага, ошибки — через поток.

## 5. Настоящая версия Flutter

`FlutterSdkRepositoryImpl.sdkFor(projectPath)`: путь — как сейчас (`flutterExecutableFor`, с fvm);
версия и канал — из `flutter --version --machine` этого исполняемого файла (`frameworkVersion`,
`channel`), `isPreview: false`. Нет SDK или команда упала — `version: null`, форма показывает «SDK не
найден» как сейчас. `doctor()` остаётся ненастоящим (класс оставляет его made-up, Настройки
продолжают показывать Preview у отчёта).

## Ошибки и края

| Случай | Поведение |
| --- | --- |
| Цель появилась между проверкой и «Создать» | `flutter create` пишет в существующую папку без ошибки — поэтому репозиторий перед первым шагом повторяет `checkTarget` и падает на `flutter create` со строкой «The folder already exists» |
| Нет Flutter SDK | «Создать» и так недоступно (форма); если путь пропал — шаг `flutter create` падает с «Flutter SDK not found» |
| Нет сети на `pub add` | шаг скелета падает с выводом pub; проект добавляется (раздел 3) |
| Сеть висит | «Остановить» |
| Не задан git user | первый коммит падает с выводом git; проект добавляется |
| Выход во время создания | процесс убит, проект не добавлен |
| Длинный вывод | в шаге хранятся последние 200 строк, показываются 6 |

## Тестирование

- **Репозиторий** — с подменённым запуском процессов (интерфейс-конструктор, как у остальных
  репозиториев, которые оборачивают процессы): точные команды и аргументы для каждого шаблона и
  переключателя; порядок шагов = `creationStepsFor`; упавший шаг останавливает поток, следующие
  `pending`; отмена и `dispose` убивают текущий процесс; подстановка `{{package}}`; вставка
  `generate: true`, включая `pubspec.yaml` без `flutter:`; «git not found»; повторная проверка цели;
  добавление и доверие проекта на успехе и на неудаче после `flutter create`, но не после неудачи
  самого `flutter create`; пин `control` равен пину `pubspec.yaml` репозитория.
- **Контроллер** — «Остановить»; `projectId` в `completed` и `failed`.
- **Виджеты** — кнопки в каждом состоянии; Preview-частей нет; «Открыть проект» выбирает проект и,
  с «Открыть чат», начинает чат; без него — только выбирает.
- **Версия Flutter** — разбор JSON `--version --machine`, ошибка команды → `version: null`.
- **Opt-in шаблонный тест** (`FLUTTER_RUN_TEST=1`, тег `flutter`, нужна сеть — как шаблонный тест
  знаний M3): настоящий
  репозиторий создаёт проект во временной папке без git, затем `flutter analyze` и `flutter test`
  в нём проходят без замечаний; временная папка удаляется и при падении.
- `FakeProjectCreationRepositoryImpl` удаляется; виджетные тесты берут заглушку из `test/support/`.

## Решения M4

- Скелет пишет приложение, не агент: секунды, без токенов и разрешений, одинаково каждый раз
  (выбор пользователя). Цена ошибки: если агент нужен для подгонки скелета, это первый ход чата.
- Шаблон — папка ассетов, а не строки в Dart: файлы читаемы и проверяемы сгенерированным проектом.
- Git-источники проектов — позже (выбор пользователя).
- Проект добавляется в сайдбар сам, но не выбирается; открывает его кнопка.
- Новый проект доверенный: его файлы написало приложение.
- Без таймаутов, с «Остановить»; вопрос при выходе создание не считает.
- Только английский в скелете; другой язык — ещё один `.arb`.
- Настоящая версия Flutter входит в M4 (её показывает форма); `doctor` остаётся Preview.
