# Навигация по коду в виде «Код»: hover, определение, ссылки, форматирование

Ветка `code-navigation` (от `main`). Следующий шаг после анализа Dart
(`docs/superpowers/specs/2026-11-04-dart-analysis-design.md`): тот же `dart language-server`
отвечает ещё на четыре запроса — hover, определение, ссылки и форматирование. Плюс история
переходов и вкладки только для чтения для кода вне проекта.

## Установленные факты (2026-11-05)

- В приложении уже есть свой LSP-клиент: `LspConnection` (`request` с тайм-аутом, `notify`),
  `DartAnalysisServer` (`open`/`change`/`close`, `complete`, `resolve`, `diagnostics`,
  `analyzing`) и `IDartAnalysisRepository` на проект. Перед запросом дополнения репозиторий сразу
  отправляет неотправленный текст (`_flush`) — так же будут делать новые запросы.
- Сервер отвечает:
  - `textDocument/hover` → `{contents: {kind: markdown, value}, range}`: в `value` — блок кода с
    объявлением, затем dartdoc; на пробеле — `null`;
  - `textDocument/definition` → `Location[]` или `LocationLink[]` (`targetUri`,
    `targetSelectionRange`); код Flutter и пакетов приходит как `file://` пути во Flutter SDK и в
    pub cache;
  - `textDocument/references` (`context.includeDeclaration`) → `Location[]`;
  - `textDocument/formatting` (`options: {tabSize: 2, insertSpaces: true}`) → `TextEdit[]`, при
    синтаксической ошибке — `null`; ширина строки берётся из настроек проекта.
- `re_editor` 0.10.0:
  - `CodeEditor(readOnly: true)` запрещает правку, поиск работает;
  - клик ставит каретку сам: после ⌘-клика каретка уже на имени;
  - позиции по координате (`calculateTextPosition`) в публичном API нет; позицию под указателем
    считаем сами по моноширинному шрифту, как уже считается место списка дополнения
    (`_listPosition`), со сдвигом прокрутки и свёрнутыми блоками (`index2lineIndex`).
- `CodeTabsController.open(path, line:)` уже открывает файл на строке; состояние вкладок хранится
  путями относительно проекта. Наблюдение за диском (`files.watch(root)`) видит только проект.
- Markdown рисует `flutter_markdown_plus` (уже в зависимостях, им пользуется чат).
- Настройки — `AppSettings` (JSON), раздел «Основные» — `general_settings_section.dart`.

## 1. Что видит пользователь (только `.dart`)

- **Hover:** указатель 500 мс на имени — под ним всплывашка:
  - объявление моноширинным (`Container({Key? key, …})`), ниже dartdoc как markdown;
  - ошибка или предупреждение под указателем — сверху в той же всплывашке (отдельной подсказки
    ошибок больше нет);
  - до ~300 px высотой, дальше прокрутка; указатель можно завести внутрь (прокрутить,
    выделить); закрывается, когда указатель ушёл с имени и всплывашки, при наборе и по Esc.
- **Переход к определению:** ⌘-клик по имени или F12 с кареткой на нём:
  - одно определение — его вкладка, каретка на имени (строка и столбец);
  - несколько — всплывашка ссылок (ниже) со списком определений;
  - нет — «Определение не найдено» внизу редактора на ~2 с.
- **Ссылки (⇧F12):** всплывашка как ⌘P — «Ссылки на `name` (12)»:
  - строка: файл, номер строки, обрезанная строка кода с именем жирным; сначала файлы проекта,
    по пути;
  - набор фильтрует по имени файла и коду; ↑↓, Enter — открыть, Esc — закрыть;
  - ничего — «Ссылок нет» на ~2 с.
- **Назад / вперёд:** ⌃- и ⌃⇧-, а также кнопки ← → справа в полосе вкладок (серые, если некуда):
  - перед каждым прыжком — определение, строка ссылок, ⌘P — запоминается, где была каретка
    (файл, строка, столбец); обычные клики и набор не записываются;
  - до 50 мест на проект; новый прыжок стирает «вперёд»; место в закрытой вкладке открывает
    файл снова (если файла нет — место пропускается).
- **Вкладки только для чтения** — файлы вне проекта (Flutter, Dart SDK, pub cache):
  - 🔒 и `package:` имя на вкладке (`package:flutter/src/widgets/container.dart`) — из
    `.dart_tool/package_config.json` проекта; файлы SDK — `dart:core/…`; прочее — путь с `~`;
  - текст не правится, поиск (⌘F) работает, замена скрыта, ⌘S ничего не делает;
  - hover, ⌘-клик и ⇧F12 внутри работают — можно идти глубже по коду Flutter;
  - не восстанавливаются после перезапуска, не считаются несохранёнными, диск не наблюдается
    (файл читается один раз); тот же файл снова — та же вкладка; ⌘W закрывает.
- **Форматирование:**
  - при включённой настройке сохранение Dart-вкладки сначала форматирует её: ⌘S и «Сохранить
    всё» (выход, отправка агенту, удаление проекта);
  - правки — одним шагом отмены (⌘Z возвращает неформатированный текст), каретка остаётся на
    том же коде;
  - сервер не ответил за 2 с, не запущен или в файле синтаксическая ошибка — файл сохраняется
    как есть, без сообщений;
  - ⇧⌥F форматирует без сохранения, при любой настройке.
- **Настройка:** «Настройки → Основные» — «Форматировать Dart-файлы при сохранении» /
  “Format Dart files on save”, включена по умолчанию.
- **Без анализа** (не Dart, сервер запускается или недоступен): hover только с ошибками, F12 и
  ⇧F12 — «Определение не найдено» / «Ссылок нет», подвал анализа уже объясняет почему. Набор
  ничто не блокирует; ответ, пришедший после сдвига каретки или правки, отбрасывается.

## 2. Устройство

- `lib/src/common/dart_analysis/`:
  - модели: `DartHover` (markdown, `LspRange? range`), `LspLocation` (path, `LspRange range`;
    `fromJson` читает и `Location`, и `LocationLink` — `targetSelectionRange`), `LspTextEdit`
    (range, newText);
  - `DartAnalysisServer`: в `initialize` — `hover.contentFormat: [markdown, plaintext]`,
    `definition`, `references`, `formatting`; методы
    `hover(path, position) → Future<DartHover?>`,
    `definition(path, position) → Future<List<LspLocation>>`,
    `references(path, position) → Future<List<LspLocation>>` (с объявлением),
    `format(path) → Future<List<LspTextEdit>?>`.
- Фича `code_view`:
  - `IDartAnalysisRepository` — те же четыре метода с текущим текстом файла (`text`), как
    `complete`: сначала отправка текста, потом запрос; без сервера или при ошибке — `null` /
    пусто; `format` с тайм-аутом 2 с.
  - `CodeDocument.readOnly` (и `label`); `CodeTabsController.open(path, line:, column:)` —
    файл вне `root` открывается только для чтения; такие вкладки не попадают в сохранённое
    состояние и не следят за диском. Имя `package:` — функция от `package_config.json`
    (читается при первом прыжке наружу, кэш на `CodeWorkspace`).
  - `CodeNavigationHistory` на `CodeWorkspace`: `record(place)`, `back()`, `forward()`,
    `canGoBack`/`canGoForward` (`ChangeNotifier`), лимит 50; место — путь, строка, столбец.
  - `CodeNavigationController` на вкладку (как `DartCompletionController`): hover по указателю
    с задержкой 500 мс и отменой устаревших ответов; `goToDefinition()`, `findReferences()`;
    результат — открыть место через `CodeTabsController` с записью в историю или показать
    всплывашку / сообщение.
  - Виджеты: `CodeHoverCard` (объявление, dartdoc, ошибка), `CodeReferencesDialog` (по образцу
    `code_quick_open.dart`), кнопки ← → в `code_tab_bar.dart`, сообщение внизу редактора.
    Клавиши — через `Shortcuts`/`Actions` над редактором, как ⌃Space; ⌘-клик — `Listener`
    поверх редактора: после отпускания с ⌘ — определение для каретки.
  - Форматирование: `formatDocument(document, analysis)` применяет правки снизу вверх одной
    отменяемой операцией и переносит каретку; `CodeTabsController.save`/`saveAll` вызывают его
    для Dart-вкладок, если `formatOnSave()` (функция, переданная в `CodeViewRegistry` из
    настроек) возвращает `true`.
  - `AppSettings.formatOnSave` (по умолчанию `true`) и строка в «Основных».
- Риск: ⌘-клик в `re_editor` может не ставить каретку так же, как обычный клик. Первая задача
  плана проверяет это тестом; если не ставит — позиция берётся из координаты клика тем же
  расчётом, что и для hover.

## Ошибки и края

| Случай | Поведение |
| --- | --- |
| Сервер не запущен / упал | Hover — только ошибки; F12, ⇧F12 — сообщение; ⌘S сохраняет без форматирования |
| Ответ после правки или сдвига каретки | Отбрасывается |
| Определение в файле, которого уже нет | «Определение не найдено» |
| Определение вне проекта | Вкладка только для чтения |
| Синтаксическая ошибка при ⌘S | Сохранение без форматирования |
| Форматирование не изменило текст | Ни правок, ни шага отмены |
| Вкладка только для чтения и ⌘S, ⇧⌥F | Ничего |
| Место истории в удалённом файле | Пропускается |
| Нет `package_config.json` | Ярлык — путь с `~` |

## Тестирование

- Сервер на `ScriptedLspProcess`: четыре запроса и разбор ответов — `Location` и
  `LocationLink`, `null`, пустой список, ошибка; объявленные возможности в `initialize`.
- Репозиторий: текст уходит до запроса; без сервера — пусто; тайм-аут форматирования.
- Модели: позиция под указателем с прокруткой и свёрнутым блоком; применение правок
  форматирования (каретка, один шаг отмены); ярлык `package:` из `package_config.json`; история
  (лимит, «вперёд» стирается, пропуск удалённых).
- Виджеты (macOS): hover через 500 мс с документацией и ошибкой, закрытие набором и Esc;
  ⌘-клик и F12 открывают файл с кареткой на имени; определение снаружи — только чтение, не
  правится, не восстанавливается; несколько определений — всплывашка; ссылки: фильтр, Enter, Esc;
  назад/вперёд клавишами и кнопками; ⌘S форматирует и сохраняет, ⌘Z отменяет форматирование,
  настройка выключена — без форматирования, синтаксическая ошибка — сохранение как есть; ⇧⌥F;
  всплывашки 900×600 en/ru, светлая/тёмная.
- Настоящий сервер (opt-in `DART_LSP_TEST=1`): hover на виджете Flutter, определение в Flutter
  SDK, ссылки, форматирование.

## Решения

- Всё через уже запущенный `dart language-server`; отдельный `dart format` не запускается.
- Код вне проекта — вкладки только для чтения, не восстанавливаются.
- Ссылки — всплывашка как ⌘P, а не панель.
- Форматирование при сохранении включено по умолчанию, с настройкой; ⇧⌥F — вручную.
- История — только прыжки (определение, ссылки, ⌘P), не каждый клик.
