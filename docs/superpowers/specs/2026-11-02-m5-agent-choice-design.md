# M5: Выбор агента

Веха M5 из `docs/PLAN.md`. Готово, когда: в Настройках → Агенты Codex, Gemini CLI и свой ACP-агент
показывают настоящий статус и входят из приложения; агента можно выбрать агентом по умолчанию и для
нового чата до первого сообщения; Codex в чате получает правила и инструменты приложения так же, как
Claude, и вызывает `list_skills`.

## Цель и рамки

Сейчас всё приложение рассчитано на одного агента: `AgentHub` держит фиксированную карту
`{'claude': AgentDefinition.claude}`, статус проверяется CLI Claude, Codex и Gemini — Preview-карточки
(«Появится в M5»), «Добавить ACP-агента» — тоже. M5 делает агентов общими: определение агента —
данные, статус — ACP-рукопожатие плюс небольшая проверка входа у встроенных, вход — ACP
`authenticate`, знания M3 — каждому агенту по его каналу.

Решения пользователя: настоящими становятся Codex, Gemini CLI и свой ACP-агент; вход — в приложении,
API-ключи не вводятся в приложение, а берутся из переменных окружения оболочки; знания M3 — все
(инструменты для всех, правила по каналу агента).

Вне рамок: установка агентов из приложения (всё идёт через `npx`, «установлен» = есть подходящий
Node.js), глобальные бинарники `gemini`/`codex` (это свой агент), поле ввода API-ключа, Vertex AI и
шлюзы (gateway) как способы входа, stdio-мост к серверу приложения (всем трём агентам хватает HTTP).

## Установленные факты (проверены перед спекой, 2026-11-02)

- `@google/gemini-cli` 0.66.0 (Node ≥ 22): ACP — флаг `--acp` (`--experimental-acp` устарел).
  `initialize` отвечает: `authMethods` `oauth-personal` («Log in with Google»), `gemini-api-key`
  (`_meta.api-key.provider: google`), `vertex-ai`, `gateway`; `agentCapabilities`: `loadSession`,
  `promptCapabilities {image, audio, embeddedContext}`, `mcpCapabilities {http: true, sse: true}`.
  Logout не заявлен.
- `@agentclientprotocol/codex-acp` 2.5.0 (Node ≥ 20) — новый дом адаптера; `@zed-industries/codex-acp`
  помечен deprecated. `initialize`: `authMethods` `api-key` (`_meta.api-key.provider: openai`),
  `chat-gpt`; `agentCapabilities`: `auth.logout`, `loadSession`, `promptCapabilities {embeddedContext,
  image}`, `sessionCapabilities {… systemPrompt}`, `mcpCapabilities {http: true, sse: false}`,
  `_meta.authStatus` (у вошедшего пользователя проба увидела `{}` — форму уточнить в плане). Ключ —
  `CODEX_API_KEY`, иначе `OPENAI_API_KEY`, когда выбран способ `api-key`.
- codex-acp принимает в `session/new` и `session/load` поле `systemPrompt: {mode: "append", content:
  [{type: "text", text}]}` (другие режимы и не-текстовые блоки — `invalidParams`).
- `dart_acp_sdk` 0.1.1 имеет `AuthenticateRequest` и `LogoutRequest`, но не поле `systemPrompt`
  запросов сессии — оно добавляется в сырой JSON.
- На этой машине: Codex CLI 0.149 вошёл через ChatGPT (`~/.codex/auth.json`); Gemini CLI глобально не
  установлен, `~/.gemini` без учётных данных; Node 22.23.
- Адаптер Claude закреплён на 0.96.0 (последний — 0.99.1); M5 его не меняет.

## 1. Определения агентов и свои агенты

Встроенные — в `common/acp/agent_definition.dart`, каждый на точной версии (поднимается с релизами
приложения, как Claude):

| Агент | Команда | Node | Канал правил |
| --- | --- | --- | --- |
| Claude Code | `npx -y @agentclientprotocol/claude-agent-acp@0.96.0` (как сейчас) | 22+ | `claudeMeta` |
| Codex | `npx -y @agentclientprotocol/codex-acp@2.5.0` | 20+ | `systemPrompt` |
| Gemini CLI | `npx -y @google/gemini-cli@0.66.0 --acp` | 22+ | `firstMessage` |

`AgentDefinition`:
- `rulesChannel` (`enum RulesChannel { claudeMeta, systemPrompt, firstMessage }`) заменяет
  `acceptsClaudeMeta`;
- `keyVariables` — способ входа по ключу → имена переменных (Codex `api-key` → `CODEX_API_KEY`,
  `OPENAI_API_KEY`; Gemini `gemini-api-key` → `GEMINI_API_KEY`);
- `source` (`builtin` / `custom`).

Свои агенты — drift-таблица `custom_agents` (схема v9): `id` (`custom:<n>`), `name`, `executable`,
`arguments` (JSON-список), `environment` (JSON-карта), `rulesChannel` (по умолчанию `firstMessage`).
Настройки → Агенты: «Добавить ACP-агента» — форма: имя, команда и аргументы отдельными полями (без
оболочки), строки `KEY=value`, канал правил; правка и удаление. Чаты удалённого агента хранят историю,
но не продолжаются: «Этот агент удалён».

`AgentHub` берёт определения из потока (встроенные + свои): новый агент — новый слот; изменённый —
процесс перезапускается, когда ни один его чат не занят; удалённый — процесс закрывается.

## 2. Статус и вход

`IAgentProbe` (фича `agents`) на агента:
1. Предпроверка: исполняемый файл найден, Node.js не старше нужного — иначе «Не установлен» с
   подсказкой (как у Claude).
2. ACP-рукопожатие: агент в своей группе процессов, `initialize` → версия, способы входа,
   возможности (HTTP/SSE MCP, `loadSession`, канал системного промпта); затем процесс убивается.
   Лимит 60 с (первый `npx` качает пакет), пока — «Проверяю…». Не ответил / упал — новый статус
   `failed` с одной строкой причины.
3. Вход у встроенных: Claude — `auth status --json` (как сейчас); Codex — `_meta.authStatus`
   рукопожатия, запасной путь — есть `~/.codex/auth.json` или задан `CODEX_API_KEY`/`OPENAI_API_KEY`;
   Gemini — есть `~/.gemini/oauth_creds.json` или задан `GEMINI_API_KEY`. Свой агент — «Готов» с
   пометкой «вход проверяется в первом чате».
4. Когда: один раз в фоне при старте и при открытии Настроек → Агенты / по «Обновить». Результаты —
   в памяти.

Вход:
- Claude — как сейчас (команда входа, вывод в диалоге).
- Входы через браузер (Codex `chat-gpt`, Gemini `oauth-personal`): новый
  `AgentHub.authenticate(agentId, methodId)` шлёт ACP `authenticate` по соединению агента (запуская
  его при необходимости); браузер открывает агент. Диалог ждёт без лимита, с «Отменой». После успеха —
  новая проверка статуса и повтор чатов этого агента в `needsAuth` (как у Claude).
- По ключу: поля для ключа нет. Карточка называет переменную для профиля оболочки и просит
  перезапустить приложение (окружение оболочки читается при старте). Когда переменная есть —
  «Использовать API-ключ» шлёт `authenticate` с этим способом (адаптерам нужен этот вызов).
- Не поддержанные приложением способы (Gemini `vertex-ai`, `gateway`; шлюз Codex) показываются как
  «настройте в самом агенте».
- Выход: Claude — как сейчас; Codex — ACP `logout` (заявлен); Gemini и свои агенты без `auth.logout` —
  без кнопки.
- В чате: ответ агента «нужен вход» (`-32000`) показывает баннер входа чата (сейчас только Claude) со
  способами этого агента.

## 3. Знания для каждого агента

`SessionContextRepository` строит MCP-серверы и правила чата по агенту и его рукопожатию.

- MCP-серверы: всем агентам — сервер приложения (HTTP на `127.0.0.1`, токен чата), Dart MCP, свои.
  HTTP- и SSE-серверы уходят только агентам, заявившим их поддержку; пропущенные (SSE у Codex) — одно
  уведомление хаба на старт чата. stdio — всегда.
- Правила — тот же `buildRulesPrompt`; без того, что агент читает сам:

| Агент | Как приходят правила | `.claude/rules` проекта | `AGENTS.md` проекта |
| --- | --- | --- | --- |
| Claude | `_meta.systemPrompt.append` | не включаются (читает сам) | включается |
| Codex | `systemPrompt: {mode: append, content: [text]}` в `session/new` / `session/load` | включаются | не включается (читает сам) |
| Gemini | ресурс `flutter-agent://rules` (`text/markdown`) в первом сообщении | включаются | включается |
| Свой | канал из формы (по умолчанию первое сообщение) | включаются | включается |

- «Первое сообщение» — первый `session/prompt` новой ACP-сессии. После `session/load` история уже
  содержит правила, ничего не добавляется. Правила фиксируются на старте сессии, как у Claude.
- Скиллы: всем — через MCP-инструменты приложения (`list_skills`, `load_skill`); меню F фильтрует,
  что отдаёт приложение; `/имя` работает у всех (у всех трёх `embeddedContext`). Список `skills` —
  только Claude; свои системы скиллов Codex и Gemini не трогаются.
- Автоматическое разрешение инструментов приложения: Claude — `allowedTools` (как сейчас); остальным —
  `PermissionBroker` сам разрешает запрос, если инструмент принадлежит серверу `flutter_code_agent`.
  Как это видно в запросах Codex и Gemini — проверить в плане; если не различить — обычный вопрос.
- Модель, усилие, режим уже идут из `configOptions` агента и хранятся по агенту.

## 4. Выбор агента в чате и агент по умолчанию

- По умолчанию: в Настройках → Агенты им может стать любой агент, кроме «Не установлен» и «Ошибка»
  (агент, которому нужен вход, — можно). Удалённый или недоступный агент по умолчанию → новые чаты с
  Claude, карточка об этом говорит.
- Новый чат начинается с агента по умолчанию. До первого сообщения чип «Агент» предлагает всех
  агентов со статусом: «Готов» и «Нужен вход» выбираются, «Не установлен» и «Ошибка» — серые с причиной.
  Выбор меняет `agentId` чата (`setAgent(sessionId, agentId)`; отказ, если у чата уже есть
  ACP-сессия — она появляется только с первым сообщением). Чипы модели, усилия и режима переходят на
  агента и его значения по умолчанию. После первого сообщения чип заблокирован с подсказкой «Агента
  нельзя сменить после первого сообщения».
- В сайдбаре у строки чата маленькая метка агента — только если это не Claude.
- В одном проекте могут быть чаты разных агентов; у каждого агента свой процесс (слот хаба).
- Убираются: «Появится в M5» в чипе «Агент» и в Настройках, Preview-карточки агентов.

## Ошибки и края

| Случай | Поведение |
| --- | --- |
| Первый `npx` качает пакет | Проверка при старте (60 с) наполняет кэш; чат до неё — лимит хаба 60 с |
| Команды своего агента нет | `failed`: «command not found: …» |
| Свой агент не говорит ACP | `failed`: «no ACP answer to initialize» (лимит или не-JSON) |
| Вход завис | «Отмена» закрывает соединение агента (убивает группу), чаты остаются в `needsAuth` |
| Ключ задан при запущенном приложении | «Перезапустите приложение, чтобы подхватить ключ» |
| Удаление своего агента с занятым чатом | Вопрос; процесс убивается; чаты — «Этот агент удалён» |
| Свои SSE-серверы у Codex | Пропущены, одно уведомление хаба на старт чата |
| Агент упал в чате | Как сейчас: ошибка чата с «Повторить» |
| Агент по умолчанию удалён | Новые чаты — Claude, карточка говорит |

## Тестирование

- Проверка статуса: сценарный ACP-агент (`test/support/fake_agent*`) — рукопожатие, `failed`, лимит,
  разбор способов входа и возможностей; проверки входа встроенных — во временном HOME и окружении.
- Хаб: изменение определений на ходу (добавление; правка — перезапуск, когда свободен; удаление);
  `authenticate` и его отмена; повтор чатов в `needsAuth`.
- Контекст сессии: каждый канал правил (`systemPrompt` в сыром `session/new`/`session/load`; ресурс
  только в первом prompt новой сессии, не после `load`); таблица `AGENTS.md`/`.claude/rules`;
  отбор HTTP/SSE-серверов.
- Разрешения: инструменты приложения у не-Claude агентов разрешаются сами, прочие — с вопросом.
- Свои агенты: миграция drift v9, добавление/правка/удаление.
- Виджеты: пункты и состояния чипа «Агент»; отказ `setAgent` после первого сообщения; выбор агента по
  умолчанию; форма своего агента; диалоги входа (браузер, ключ).
- Opt-in (`FLUTTER_AGENT_TEST=1`, тег `agent`): Codex — рукопожатие и один prompt, где Codex вызывает
  `list_skills`; Gemini — только рукопожатие и способы входа.

## Решения M5

- Агент — данные (`AgentDefinition` + `custom_agents`), статус — общее ACP-рукопожатие плюс проверка
  входа у встроенных (выбор пользователя: подход A).
- Codex — `@agentclientprotocol/codex-acp` (старый пакет устарел); все три закреплены на версиях.
- API-ключи — только из окружения; в приложении ключей нет.
- Правила — по каналу агента; то, что агент читает сам (`.claude/rules` у Claude, `AGENTS.md` у
  Codex), не дублируется.
- Агент меняется только до первого сообщения; метка агента в сайдбаре — только для не-Claude.
- Адаптер Claude остаётся на 0.96.0.
