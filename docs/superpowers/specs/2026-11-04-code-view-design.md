# Вид «Код»: проводник и редактор проекта

Ветка `code-view` (от `ux-round-1`, до его слияния — затем перенести на `main`). План пишется по этому
документу. Первый шаг большого «как VS Code»: ядро редактора. Диагностика, подсказки и hover от Dart
analysis server — следующая веха.

## Установленные факты (2026-11-04)

- Сейчас файлы открываются системным приложением: `ProjectsController.openPath` (Changes,
  строки Run через `WorkspaceConfigWidgetState.openRunFile`). Своего редактора нет.
- `re_editor` 0.10.0 (Reqable, 2026-07-01, не discontinued): `CodeEditor`, `CodeLineEditingController`
  (`fromText`, `text`, `codeLines` — неизменяемое значение на каждую правку, `lineBreak`, `canUndo`,
  `selectLine`), `CodeFindController` (поиск и замена), `CodeHighlightTheme` с языками
  `re_highlight` 0.0.3 (197 языков: dart, yaml, json, swift, kotlin, gradle, groovy, xml, markdown,
  objectivec, cpp, bash, shell, properties, ini, css, javascript, typescript, ruby, plaintext).
  Тянет `isolate_manager ^4.1.5` (последний — 6.3.2): совместимость с нашими зависимостями
  проверяется `flutter pub get` в первой задаче.
- drift — схема v10. Выход с вопросом — `app_close` (`busyChats`, `askBeforeQuit`); общий счётчик
  занятых чатов лежит в `common/chat_queue/queued_chats.dart` — образец для несохранённых файлов.
- Сочетания `⌘N ⌘K ⌘\ ⌘J ⌘R ⇧⌘R ⌘, Esc` заняты; `⌘S ⌘W ⌘P ⌘F` свободны.

## 1. Раскладка и переключение

- Над колонкой чата, по центру, `SegmentedButton`: **Чат | Код**. Выбор — на проект: все чаты проекта
  видят один вид «Код» с одними вкладками. Без выбранного проекта переключателя нет.
- Сайдбар и правая панель (Changes, Run, Plan) остаются. В «Коде» колонка чата становится:
  - **Проводник** (240 px, тянется 180–480): дерево папок проекта. Папки раскрываются лениво.
    `.git`, `build`, `.dart_tool` не показываются; игнорируемое `.gitignore` — приглушено. Дерево
    следует за диском (правки агента, новые и удалённые файлы).
  - **Редактор**: вкладки сверху (● — несохранено, ✕ и средняя кнопка закрывают), под ними код с
    номерами строк, подсветкой, сворачиванием, поиском ⌘F (и заменой из него), ⌘S — сохранить,
    ⌘W — закрыть вкладку, ⌘P — быстрое открытие по имени файла. Пустой редактор — подсказка
    «Выберите файл слева или нажмите ⌘P».
- Файл из Changes и строка из логов Run открываются в «Коде» на нужной строке (переключатель
  переходит на «Код»); уже открытая вкладка переиспользуется. «Открыть в приложении по умолчанию» —
  в контекстном меню вкладки и строки дерева.
- Режим Чат/Код, вкладки, активная вкладка и ширина проводника запоминаются на проект (drift v11,
  таблица `code_view_state`) и восстанавливаются при запуске; пропавший файл из списка вкладок
  убирается молча.

## 2. Устройство

Новая фича `lib/src/feature/code_view/` по `docs/AI_INSTRUCTIONS.md`.

- `IProjectFilesRepository` (файловая система и `git`, через конструктор):
  - `list(String dir) → Future<List<FileNode>>` — записи одной папки (папки сначала, по имени),
    с пометкой `ignored` по `git check-ignore --stdin` (вне git-репозитория — ничего не игнорируется);
  - `watch(String root) → Stream<FileChange>` — `Directory.watch(recursive: true)`, без `build/`,
    `.dart_tool/`, `.git/`, слитые за 100 мс; долгоживущий поток по правилам «Stream-Returning
    Methods», отписка в `dispose`;
  - `read(String path) → Future<FileContent>` — текст и `FileStamp` (время изменения и размер);
    отказ `FileNotTextException` (NUL в первых 8 КБ или не UTF-8) и `FileTooLargeException` (> 5 МБ);
  - `write(String path, String text, {required FileStamp? expected}) → Future<FileStamp>` — через
    временный файл и переименование; `FileChangedOnDiskException`, если штамп на диске не равен
    `expected`; `expected: null` — запись без проверки (перезапись по согласию, восстановление
    удалённого).
- `FileTreeController` — раскрытые папки, их содержимое, обновление по `watch`; дерево рисуется одним
  `ListView.builder` по плоскому списку видимых строк.
- `CodeTabsController` (на проект) — вкладки и активная; на каждый открытый файл один `CodeDocument`:
  `CodeLineEditingController`, `FileStamp` с диска, сохранённое значение `codeLines`. Несохранено —
  когда текущее `codeLines` не то, что сохранено (отмена до сохранённого снимает ●), по образцу
  `alternativeVersionId` VS Code. Документы живут, пока открыта вкладка: переключение вкладок,
  Чат/Код и проектов их не пересоздаёт (отмена, курсор, прокрутка сохраняются).
- `CodeEditorView` — только окно на активный документ: `CodeEditor` с темой из `context.colors`,
  моно-шрифт `AppText.mono`, язык по расширению (неизвестное — plaintext).
- `common/unsaved_files/` — счётчик несохранённых файлов по проектам (как `queued_chats.dart`),
  чтобы `app_close` и чат читали его без импорта `feature/code_view`.

## 3. Диск и агент

- Файл изменился на диске (агент, git, другой редактор):
  - вкладка без правок — тихо перечитывается, курсор и прокрутка остаются;
  - вкладка с правками — полоса «Файл изменён на диске» с **Загрузить с диска** и **Оставить мои**;
  - свою запись приложение узнаёт по штампу и полосу не показывает.
- ⌘S, когда файл на диске новее прочитанного: вопрос «Файл изменён на диске. Перезаписать?» —
  **Перезаписать** / **Сравнить позже** (отмена).
- Файл удалён: вкладка помечена «Удалён», текст остаётся; ⌘S создаёт его заново.
- Агент видит только диск: отправка сообщения в чат, когда в его проекте есть несохранённые файлы, —
  полоса над полем «2 несохранённых файла — агент видит версию с диска» с **Сохранить все** и
  **Отправить так**.
- Потери нет без вопроса: закрытие несохранённой вкладки, удаление проекта и выход из приложения
  спрашивают **Сохранить** / **Не сохранять** / **Отмена**. Выход спрашивает всегда, даже если
  «спрашивать перед выходом» выключено (это про занятые чаты).

## Ошибки и края

| Случай | Поведение |
| --- | --- |
| Бинарный файл / не UTF-8 | «Не открывается в редакторе» и «Открыть в приложении по умолчанию» |
| Файл > 5 МБ | То же |
| Картинка (png, jpg, jpeg, gif, webp) | Показывается картинкой, только просмотр |
| Неизвестное расширение | Обычный текст без подсветки |
| Нет прав на чтение/запись | Строка с ошибкой; вкладка остаётся несохранённой |
| Папка проекта пропала | Проводник: «Папка проекта не найдена» |
| Проект не git-репозиторий | Ничего не приглушается |
| Тысячи файлов в папке | Плавно: плоский ленивый список |
| Строки CRLF | Сохраняются CRLF (`lineBreak` контроллера) |

## Тестирование

- Репозиторий на временных папках: порядок и пометка `ignored`, без git, бинарный и большой файл,
  атомарная запись, устаревший штамп, `watch` (создание, правка, удаление, исключённые папки).
- Контроллеры: открытие, переиспользование вкладки, ●, отмена до сохранённого, перечитывание чистой
  вкладки, полоса конфликта, удалённый файл, запоминание и восстановление вкладок (миграция v10 → v11).
- Виджеты: переключатель Чат | Код, дерево (раскрытие, приглушённое), вкладки, ⌘S ⌘W ⌘P ⌘F, полоса
  конфликта, вопрос при закрытии, открытие из Changes и Run на строке, полоса «несохранённые» в чате,
  вопрос при выходе. Тема в светлой и тёмной, русские строки.
- Руками: редактирование настоящего проекта, правка агентом открытого файла, большой файл.

## Решения

- Редактор — `re_editor`; файловое дерево, вкладки, сохранение и тема — свои.
- Документ отдельно от вида, «несохранено» — по значению `codeLines`, диск — источник правды, штамп
  проверяется перед каждой записью.
- Агенту — только сохранённое; перед отправкой с несохранёнными — предупреждение.
- Выход с несохранёнными спрашивает; «hot exit» (сохранить буферы и восстановить при запуске) — в
  продолжения.

## Не в этой вехе

Диагностика, автодополнение и hover (Dart analysis server, LSP), поиск по всем файлам, git-полосы у
номеров строк, разделение редактора на две колонки, встроенный терминал, hot exit, создание /
переименование / удаление файлов из проводника.
