# M2 (Запуск приложения) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Веха M2 из `docs/PLAN.md`: вкладка Run работает по-настоящему — устройства из `flutter daemon`, запуск через `flutter run --machine`, остановка, hot reload / restart, логи с разобранными ошибками («→ Отправить агенту» кладёт настоящую ошибку в черновик), адреса VM service / DTD / DevTools запуска сохраняются для M3 и M6; плюс DevTools в браузере, снимок экрана в чат и аргументы запуска по проекту.

**Architecture:** UI вкладки Run, контроллеры и интерфейсы `IDevicesRepository` / `IAppRunRepository` уже есть (UI-этап 4, на фейках). Новый слой `lib/src/common/flutter_daemon/` говорит на JSON-протоколе daemon (`[{...}]` построчно в stdin/stdout) поверх процесса в своей группе (`GroupedProcess`). Настоящие `DevicesRepositoryImpl` (один `flutter daemon` на приложение) и `AppRunRepositoryImpl` (один `flutter run --machine` на проект) заменяют фейки; фейки переезжают в `test/support/` как двойники. Разбор вывода (блоки ошибок Flutter, ошибки компиляции, необработанные исключения) — чистый класс `RunOutputParser`. Аргументы запуска — drift-таблица `run_configs` (схема v7).

**Tech Stack:** Flutter (macOS), control, freezed, drift, gen-l10n en/ru. Новых пакетов нет: URL открывается системной командой (`open` на macOS).

**Spec:** `docs/PLAN.md` (M2 и «Ключевая связка»), `docs/superpowers/specs/2026-10-28-ui-system-design.md` §3.4 (`@` и `/` меню), §3.6 (вкладка Run), §3.8 (DevTools в настройках), §3.10 (нет устройств, Flutter SDK не найден), §4 (`app_run`, «Фейковые репозитории», «База данных»). Протокол daemon — `<flutter>/packages/flutter_tools/doc/daemon.md` и `lib/src/commands/daemon.dart` (Flutter 3.47.1 на этой машине).

## Global Constraints

- Архитектура — `docs/AI_INSTRUCTIONS.md` с отличиями `CLAUDE.md`: репозитории `abstract interface` + `Impl({required this._x})`; виджеты не трогают репозитории; Sequential для load/watch, Droppable для мутаций; Stream-методы по Pattern 1 (onListen/onCancel), всегда закрываются; каждый процесс убивается в `dispose` (группой: `GroupedProcess.stop`).
- Процессы `flutter` получают `environment: ShellEnvironment.variables` (GUI-приложение не наследует `PATH`). Исполняемый файл проекта — `flutterExecutableFor(projectPath, which:)` (Task 1): fvm проекта, иначе `flutter` из `PATH`.
- Ни один тест по умолчанию не запускает настоящий `flutter`: репозитории получают `DaemonProcessStarter`, тесты подставляют `ScriptedDaemonProcess` (Task 1). Единственный тест с настоящим `flutter` — opt-in (Task 4).
- Тексты из `flutter` (метки прогресса, строки лога) показываются как есть. Заголовки и сообщения `RunError`, которые составляет репозиторий или парсер (`Compilation error`, `Hot reload failed`, `Flutter SDK not found`…), — английские: они уходят агенту (`RunError.forAgent`) и стоят рядом с английским выводом `flutter`. Всё остальное, что пишет приложение, — через `intl_en.arb` / `intl_ru.arb` (русское множественное one/few/many/other, обращение на «вы»).
- Цвета только `context.colors`, радиусы `AppRadius`, моно `AppText.mono`, шаг 4 px; у кнопок-иконок `tooltip`; окно 900×600 без переполнений.
- Новая версия схемы — step-by-step + тест `SchemaVerifier`, как v6 (`dart run drift_dev schema dump lib/src/common/database/database.dart drift_schemas/`, `dart run drift_dev schema steps drift_schemas/ lib/src/common/database/database.steps.dart`, `dart run drift_dev schema generate drift_schemas/ test/generated_migrations/`).

## Review Focus

1. Сборка падает (ошибка компиляции в `lib/main.dart`, ошибка Xcode) — состояние `RunFailed` с первой ошибкой компиляции (файл относительно проекта, строка), «→ Отправить агенту» кладёт её в черновик; процесс, умерший без `app.stop`, тоже даёт `RunFailed`, а не вечный «Сборка» (Task 3, Task 4).
2. Hot reload с ошибкой компиляции — приложение остаётся `RunRunning`, в логе строка-ошибка `Hot reload failed` и строки ошибок компиляции с файлами; кнопка не зависает, следующий reload после исправления проходит (Task 4).
3. Выход из приложения (⌘Q), смена проекта, повторный «Запуск» во время запуска — при выходе группы `flutter run` и `flutter daemon` убиты (сама программа на устройстве закрывается); смена проекта не останавливает запуск другого проекта; повторный старт сначала останавливает прежний процесс (Task 4, Task 5).
4. Flutter не найден (нет в `PATH`, fvm-SDK проекта не скачан) — в шапке Run «Flutter SDK не найден» со ссылкой в Настройки → Flutter вместо списка устройств; «Запуск» → `RunFailed` с понятным заголовком, без исключения в консоли (Task 2, Task 4).
5. Устройство пропало во время работы (симулятор закрыли, телефон отключили) — `flutter run` завершается: состояние `RunStopped` (код 0) или `RunFailed` (иначе), устройство уходит из списка, «Запуск» снова доступен после выбора устройства; лавина строк лога (тысячи в секунду) не растит память: буфер ≤ `kRunLogLimit`, блок ошибки ≤ 400 строк (Task 2, Task 3, Task 4).

Блок длиннее 400 строк отдаётся как есть на 400-й строке.
    - `Another exception was thrown: <msg>` → `error`, `RunError(title: Layout overflow | Exception, message: msg)`.
    - `[ERROR:flutter/runtime/dart_vm_initializer.cc(N)] Unhandled Exception: <msg>` и следующие строки `#N` → одна строка, `RunError(title: 'Unhandled exception', message: msg, stack, место — первый кадр из проекта)`.
    - `<path>.dart:<line>:<col>: Error: <msg>` → `error`, `RunError(title: 'Compilation error', message: msg, file, line, location: '<basename>:<line>:<col>')`.
    - Пути: `file:///<projectRoot>/x` и абсолютный путь внутри проекта → `x`; `package:<packageName>/x` → `lib/x`; иное (`package:flutter/…`) — `file` не задаётся, `location` остаётся.
    - Прочее: `error` при `isError`, `warning` при начале `Warning:`/`warning:`, иначе `info`.
