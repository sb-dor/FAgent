# Monorepo Projects Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** FAgent creates monorepo projects (a pure pub workspace with `apps/` and `packages/`), adds
apps and packages to any monorepo with "Add to project…", and runs the chosen app of a monorepo in
the Run tab.

**Architecture:** One member builder in the project creation repository serves monorepo creation
and "Add to project"; the step runner, progress screen and Stop stay as they are. Pub workspace
detection lives in `lib/src/common/pub_workspace/` and is read by projects, creation and Run. Run
stores its arguments per app and runs `flutter run` in the app's folder.

**Tech Stack:** Flutter desktop, control (`StateController`), drift (schema v12 → v13), freezed,
gen-l10n (en + ru), `yaml`.

**Spec:** `docs/superpowers/specs/2026-11-21-monorepo-design.md`

## Global Constraints

- Follow `CLAUDE.md` and `docs/AI_INSTRUCTIONS.md`: widgets → controller → repository; side
  effects only in repositories; every `Process` killed in `dispose`; colours from
  `context.colors`, radii from `AppRadius`; every user-visible string in `intl_en.arb` and
  `intl_ru.arb`.
- A one-app project is created exactly as today: same step list, same commands, same files.
  `projectTemplateFiles` order and content for a one-app project must not change.
- Monorepo root: `pubspec.yaml` with `name: <name>_workspace`, `publish_to: none`,
  `environment: sdk: ^<major>.<minor>.0` (the Dart of the chosen SDK), `workspace: [apps/*,
  packages/*]`, no `lib/`.
- Members: `apps/<folder>` for Flutter and Dart apps, `packages/<folder>` for Flutter and Dart
  packages; every member's `pubspec.yaml` has `resolution: workspace`. Members FAgent creates
  (`flutter create` / `dart create`) get the root's SDK constraint; `packages/ui` keeps its
  template's own (`^3.10.4`).
- Apps have no `lib/src/` (`lib/main.dart`, `lib/_core/`, `lib/<feature>/`); packages keep
  `lib/<name>.dart` and `lib/src/`.
- Default package names: first app `<name>_<folder>`, added member `<project>_<folder>` where
  `<project>` is the root package name without `_workspace` (or the folder name when it has no
  such suffix). `packages/ui` is named `ui`.
- Default first app folder: `app`.
- Minimum Dart for "Monorepo": `3.14` (`kMonorepoMinDart`), the version cafe_pos runs on.
- "Add to project" never runs `git add -A`: it stages `<apps|packages>/<folder>` and
  `pubspec.lock` only, commit message `Add <kind> <folder>` (kind: `Flutter app`, `Dart app`,
  `Flutter package`, `Dart package`).
- "Add to project" never edits `scripts/` or `Makefile`.
- Run arguments are per (project, app folder); `''` is the project root.
- Do not commit generated files; run `dart run build_runner build` and `flutter pub get` after
  model and ARB changes.

## Review Focus

1. A monorepo whose `pubspec.yaml` lists members explicitly (`workspace: [apps/desktop,
   packages/core]`) instead of globs: detection and the Run app list must still find every
   member. → Task 1 test `explicit member list`.
2. A folder under `apps/` without `pubspec.yaml` (a stray folder, `apps/.DS_Store`): it is not a
   member and must not crash the Run list or the add check. → Task 1 test `stray entries`.
3. "Add to project" stopped while `flutter create` runs: the half-made folder is removed and
   `pubspec.lock` restored, so `flutter pub get` at the root still works. → Task 5 test `stop
   rolls back`.
4. A user with uncommitted changes in the monorepo adds a member: only the new folder and
   `pubspec.lock` are committed, the user's changes stay unstaged. → Task 5 test `commit stages
   only the member`.
5. The app chosen in Run is deleted from disk: Run falls back to the first app instead of failing
   on start. → Task 9 test `missing app falls back`.

### Task 1: Pub workspace detection

**Files:**
- Create: `lib/src/common/pub_workspace/pub_workspace.dart`
- Test: `test/common/pub_workspace/pub_workspace_test.dart`

**Interfaces:**
- Produces:
  - `final class WorkspaceMember { String folder; String packageName; bool isFlutter; bool hasMain; }`
    — `folder` is relative to the root with `/` separators (`apps/desktop`); `isFlutter` when its
    `pubspec.yaml` lists `flutter` under `dependencies` (`sdk: flutter`); `hasMain` when
    `lib/main.dart` exists.
  - `bool isPubMonorepo(String root)` — root `pubspec.yaml` has a `workspace:` key and the root
    has no `lib/` directory.
  - `List<WorkspaceMember> workspaceMembers(String root)` — expands each `workspace:` entry (a
    path or a glob with `*` in one segment, as pub supports), keeps folders with a readable
    `pubspec.yaml`, sorted by `folder`.
  - `List<WorkspaceMember> runnableApps(String root)` — members under `apps/` with `isFlutter &&
    hasMain`.
  - `String? workspacePackageName(String root)` — `name:` of the root `pubspec.yaml`.
  - All synchronous file reads; callers are repositories.
